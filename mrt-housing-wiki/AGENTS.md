# LLM Wiki 維護守則與 Agent SOP (AGENTS.md)

本文件依據 Andrej Karpathy 提出的 **LLM Wiki** 核心概念設計，規範專案中知識匯入 (Ingest)、查詢檢索 (Query)、質量審計 (Lint) 與反覆修正 (Feedback Loop) 的標準作業程序。

---

## 核心原則 (Core Principles)

1. **零幻覺與嚴格來源可溯性 (Zero-Hallucination & Provenance)**
   - 知識庫內的所有實證論點、數據與結論，必須能夠 100% 追溯至 `raw/` 中的特定文獻。
   - 嚴格禁止編造未出現在文獻中的統計數據、百分比或因果推論。

2. **讀取邊界誠實揭示 (Honesty of Reading Scope)**
   - 若文獻僅取得摘要，必須在文件與中繼資料明確標示 `讀取範圍：僅依據摘要與公開紀錄`。
   - 嚴格禁止將「僅依據摘要」之文獻標記為「已讀取全文」，且不得衍生超越摘要文意的過度概括推論。

3. **純 Markdown 與雙向連結 (Plain Markdown & Wikilinks)**
   - 知識庫採用純 Markdown 檔案維護，不依賴不透明的向量資料庫或外部系統。
   - 頁面之間必須透過相對路徑或 `[[頁面名稱]]` 建立語義連結，形成可瀏覽的知識網絡 (Web of Knowledge)。

## Agent SOP 流程規範

### 1. Ingest SOP (資料匯入與萃取)
- **觸發時機**：引入新的學術研究或資料來源時。
- **步驟**：
  1. **來源檢核**：確認作者、年份、標題、典藏機構網址與實際可取得範圍（全文 vs 摘要）。
  2. **建立 Raw 記錄**：在 `raw/paper_{編號}_{id}.md` 建立不可變的文獻記錄，包含標準 YAML Frontmatter 元資料及忠實的摘要整理。
  3. **概念與實證分流**：將提取的核心理論分流至 `wiki/concepts/`，實證數據與發現分流至 `wiki/empirical-findings/`。
  4. **日誌記錄**：在 `logs/ingest.log.md` 記入文獻編號、標題、來源網址、讀取範圍、擷取觀點與建立頁面。

### 2. Lint SOP (知識庫靜態分析與審計)
- **觸發時機**：完成 Ingest、修改 Wiki 內容或發布成果前。
- **檢查項目**：
  - **Rule A (來源覆蓋度)**：每個主要論點是否有可追溯的 `raw/` 來源？
  - **Rule B (數據真實性)**：是否出現文獻未提供的數值或推論？
  - **Rule C (過度概括)**：是否有超越文獻研究範疇的結論（如將特定路線推論為全台灣，或將單一時期研究推論為全生命週期）？
  - **Rule D (超連結有效性)**：Wiki 頁面間的相對路徑與跳轉是否正確無效？有無孤立頁面？
- **處置**：若發現違規，記錄於 `logs/lint.log.md`，觸發回饋迴圈修正檔案後重新進行檢查。

### 3. Query SOP (查詢與知識問答)
- **觸發時機**：使用者提問或進行知識檢驗時。
- **檢索原則**：
  - 嚴格閉環檢索（Closed-domain）：僅使用 `wiki/` 與 `raw/` 實際收錄之文獻知識作答。
  - 回答必須包含三個區塊：
    1. **核心回答**：直接回應問題本質。
    2. **實證與文獻依據**：精確引述作者與年份。
    3. **研究限制與適用條件**：說明樣本範圍、時空背景與讀取限制。
- **日誌記錄**：記錄提問、回答全文與檢索鏈路於 `logs/query.log.md`。

## 特殊約束與禁忌事項 (Specific Prohibitions)
- **温弘裕 (2015)**：不可描述為「規劃期、施工期與通車期之比較」，其研究聚焦於信義線通車後的不同距離區間房價效果。
- **戴國正 (2011)**：不可在無文獻實證證據下，自行將「噪音、擁擠」視為該研究的實證結果；該研究核心為空間異質性、區位與車站類型差異。
- **黃麟雅 (2017)**：不可混淆為環狀線或聯開宅研究，核心為臺北市生活設施水準、交通便利性與住宅價格之關係。
- **陳品睿 (2025)**：不可將研究對象直接改稱為 TPASS 政策，其研究標的明確為雙北「1280 公共運輸定期票」。
